# 7. 🔄 技能版本更新流程 (Skill Update Workflow)

* **更新判定（先查上游，再动手）**：逐个技能对照 `技能仓库索引.md` 登记的上游仓库检查更新——看最新 release/tag，与本地 `SKILL.md` 的 `metadata.version` 及本仓库该技能目录的 git 最后提交日期比对。**版本/tag 判定不了时，一律看仓库最近提交（pushed_at）时间：最近两个月内有提交即视为「有更新」，早于两个月视为「无更新」**，不再纠结提交是否只是文档。**检查的同时复核身份**：打开仓库确认内容仍与本地技能描述吻合，发现不吻合立即回索引表纠正仓库地址，严禁对着错误仓库做更新。
* **分支规范（回溯红线）**：每个技能的版本更新**必须**独立建分支处理，分支命名 `update/<技能名>-<YYYYMMDD>`，**一个分支只更新一个技能**。严禁在 `main` 上直接更新，严禁一个分支混入多个技能的改动。完成并通过全部检查后合并回 `main`——保证任何一个技能都可单独回溯或回滚到更新前状态。
* **更新执行（确定有更新 → 直接覆盖集成）**：更新不是打补丁，也**不做增量 diff 合并**。确定有更新的技能，从索引登记的上游地址**重新克隆最新版，按新技能集成流程直接覆盖本地技能目录**重做一遍：先读懂上游新结构（上游可能重组目录）→ 无价值文件 AI 审查（文件夹一眼判断）→ 冲突清理 → 路径长度检查 → 引用完整性闭包复检（`--refs` 必须归零链上真实断链）→ 清单登记核对。本地自建的 `SKILL.md` 入口（含 Leading Words 检索元数据）保留我们的编制风格，仅同步上游版本号与能力变化；上游剔除过文件或重组过目录时，同步改写保留文档中的旧引用。
* **完成登记（两处必写）**：更新合并回 `main` 后：① `技能仓库索引.md` 该技能行的**更新日期**列写入合并日期（YYYY-MM-DD）；② 技能 `SKILL.md` 的 `metadata.version` 更新为上游新版本号。集合仓来源的技能（如 composio-community）版本跟随集合仓，登记集合仓提交日期或版本即可。
* **无更新也留痕**：检查后确认上游无实质更新的技能，不建分支不动文件，只在需要时在索引表备注列记录检查结论（如「上游 2026-06 后无提交」），避免重复检查。上游已弃用/停维护/迁移的（如 langsmith-fetch、moore-wechat-article-downloader、drawio-scientific-illustrator），在备注列注明后继仓库或停更状态，更新时以备注为准。
* **死链分类的权威对照法**（覆盖集成必用）：把 `scripts/integration_check.py` 的 `scan_dead_refs` 分别跑在「我们的新树」与「上游官方构建形态」上做差集——**上游官方形态里同样断的 = 上游固有（保留原貌、提交披露数量）；上游能解析而我们断的 = 本次集成引入（必须改写归零）**。上游官方形态取：上游仓库的发布产物/构建目录（如 CloudBase 的 `config/.claude/skills` 与 `plugin/`）、或完整源码树。注意按 (完整相对路径, 引用串) 对照，**不要只用文件名**——多子技能同名 SKILL.md 会碰撞误判。
* **已踩坑清单（2026-09-02 cloudbase / File-Organizer-MCP 实战）**：
    - macOS/BSD `cp -R src/ dst/` 源带**尾斜杠会把目录内容平铺**进目标，多目录会混成一团——批量拷贝永远用 `${d%/}` 去尾斜杠，拷完 `ls | wc -l` 对数。
    - 改写裸路径引用（`X/y.md` → `../X/y.md`）时，文件里可能本来就存在 `../X/y.md` 形态的旧链接，子串替换会把它叠成 `../../X/y.md`。正确做法：**先剥掉全部 `../` 前缀得到基准路径 → 校验 `references/<基准>` 存在 → 按文件深度重算**前缀，而不是字符串叠加。
    - 集合型上游（多子技能合一）里跨子技能相对链接，在上游「兄弟目录」形态可解析、在我们「嵌套一层」形态断——统一按深度补 `../` 改写。
    - npm 分发的 MCP 服务器类技能（如 File-Organizer-MCP）：用户从 npm 安装，**本地只保留文档层**（README/API/CHANGELOG/示例配置等），src/tests/bin 一律不拷；保留文档里指向被弃代码的引用改写为 GitHub 定 tag 链接（`blob/v<版本>/<路径>`）。
    - 上游目录重构（改名/合并）时以新结构为主，功能一致即整体采纳；我方 SKILL.md 中引用的旧目录名同步改写。
    - 并行代理/脚本不要共享 `/tmp` 固定文件名（会被相互覆盖），一律带 PID 或随机后缀。
