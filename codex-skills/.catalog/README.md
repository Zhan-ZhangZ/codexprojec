# Immutable skill catalogs

This directory is generated by `scripts/build_file_indexes.py`. Each JSON file is content-addressed by the SHA-256 of its exact bytes and lists every tracked file for one manifest skill with its path, blob SHA-1, size, and Git mode.

Catalogs are immutable. Never edit a catalog in place: stage skill or manifest changes, rerun the generator, and let it publish a new hash-named file. Obsolete catalogs are intentionally retained so manifests already fetched by older MCP clients remain verifiable. File URLs still use a mutable branch: older content may need Git blob SHA recovery, which depends on GitHub API availability and retained Git objects. Keeping catalog metadata alone does not guarantee indefinite content availability.

Validation contract:

- catalog body `version` is `1`;
- `skill_path` exactly matches the manifest entry `relative_path`;
- `file_count` and `total_bytes` match the listed files;
- every listed path is relative and contained;
- every non-router manifest skill has a catalog and a tracked `SKILL.md`.

The root `.codex-skills.tree.json` path is reserved for the MCP cache marker, including descendants. POSIX executable modes are preserved by MCP beta.5; symlink blobs materialize as target text, not live filesystem links.

CI runs generator and validator unit tests, `python3 scripts/validate_manifest.py`, and `python3 scripts/build_file_indexes.py --check`. These checks cover metadata types, catalog integrity, unregistered skills, duplicate names/paths, reserved paths, unstaged content and missing entry points. Symlink escapes and cycles fail validation; dangling upstream links are reported as warnings.
