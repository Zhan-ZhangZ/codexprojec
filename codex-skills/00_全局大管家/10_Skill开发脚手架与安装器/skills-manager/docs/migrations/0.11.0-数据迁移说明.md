# 0.11.0 数据迁移说明

> 状态：已实现并通过幂等初始化测试  
> 最后更新：2026-07-26

## 迁移目标

本次迁移增加项目运行状态、平台适配、技能包、包内技能关系、项目包部署和市场趋势快照等持久化数据，同时保留已有技能、安装、集合、扫描目录和来源记录。

## 兼容原则

- 所有迁移使用 `CREATE TABLE IF NOT EXISTS` 或幂等列检查。
- 不把技能扫描目录自动转换成项目。
- 不删除中央技能目录中的文件。
- 无可靠仓库来源的现有技能不会被自动合并。
- 新增的平台适配字段具有安全默认值；未知平台默认为未验证。
- 迁移失败时数据库初始化中止并保留原始数据库。

## 技能包聚合

只有同时满足以下条件时才允许自动提出聚合：

1. 多个技能具有相同的规范化仓库来源。
2. 它们属于同一仓库根和同一 Git 提交或可确认版本。
3. 相对路径可以安全解析且不存在路径穿越。

自动迁移只建立逻辑关系，不移动或删除现有中央技能。完整仓库快照在用户下一次重新导入或更新包时补齐。

## 回退

旧版本应用不会识别新增表，但原有表结构和技能文件仍保留。若未来新增依赖新列的不可逆迁移，必须先增加数据库版本检查和明确的版本不兼容提示。

## 验证结果

- 新表和新增列由数据库初始化流程幂等创建。
- 现有技能、集合、平台安装与扫描目录记录继续保留。
- 设置中的扫描目录不会被自动登记为项目。
- 技能包完整快照只在重新导入多技能仓库时建立。
- 完整 Rust 回归通过，结果见[0.11.0 测试验证记录](../testing/0.11.0-测试验证记录.md)。
