# 项目技能管理与技能包重构设计

> 状态：开发中  
> 目标版本：0.11.0  
> 最后更新：2026-07-26

## 1. 背景

当前应用已经具备中央技能库、技能集合、项目技能扫描、GitHub 导入、技能分类和更新检查等能力，但“扫描到一个包含技能的目录”和“用户明确添加一个项目作为安装目标”仍混在同一条工作流中。与此同时，多技能仓库会被拆成若干互不关联的技能，无法保留仓库级脚本、Hooks、插件清单、版本及更新边界。

本次重构将项目、技能包和平台适配器提升为一等领域对象，并将技能市场从静态推荐升级为带本地历史快照的多来源趋势市场。

## 2. 已确认的产品决策

- 项目管理使用独立一级页面；设置中的扫描目录只负责发现已有技能。
- 任意已存在目录都可添加为项目，不要求是 Git 仓库或已经包含技能。
- 项目统一技能目录为 `<项目>/.agents/skills`。
- 默认使用目录软链接；Windows 创建失败时必须由用户确认后才可复制，禁止静默降级。
- 外部技能先去重导入中央技能库，再安装到项目。
- 中央技能库支持单个技能和多选批量安装到项目；没有项目时仍可打开安装入口并即时添加项目。
- 项目页统一使用“安装技能”入口，来源优先级固定为中央技能库、技能集合、外部导入；不得从技能市场直接安装到项目。
- GitHub 趋势使用本地每日快照计算真实 7 天和 30 天增量；历史不足时显示“趋势估算”。
- X 使用可选 Bearer Token，接口不可用不阻塞其他市场来源。
- Hugging Face 只接纳能解析 `SKILL.md` 或明确指向技能仓库的候选。
- 平台列表由数据库启用状态和共享优先级统一驱动，Codex 始终第一，本机检测到的平台优先。
- 中央技能卡片只统计当前启用的平台，不把为兼容历史数据而保留的停用平台计入“更多平台”数量。
- 中央技能支持按不同本地项目的使用次数排序；同一项目中的多个适配路径只计为一次使用。
- 多技能仓库以技能包展示和更新，子技能仍可搜索、筛选和选择。
- 技能包默认整体安装，也允许取消非必选子技能。
- 同时支持通用技能安装和需要单独确认的平台原生安装。

## 3. 信息架构

一级页面包括：

- 中央技能库：全局规范化技能和技能包。
- 项目：用户明确维护的安装目标。
- 发现：扫描目录并发现已有技能，不负责维护项目列表。
- 技能市场：GitHub、X、Hugging Face、可信推荐和订阅源。
- 技能集合：可复用的技能选择。
- 设置：扫描目录、凭据、平台和界面设置。

项目页采用项目列表与项目详情的主从布局。空状态必须直接提供“选择目录”和“手动输入路径”，并解释即使项目中没有技能也可以添加。

## 4. 领域模型

### 4.1 项目

项目记录保存规范化绝对路径、显示名称、Git 状态、可访问状态、检测到的平台、添加时间和最近检查时间。项目技能实例与由应用创建的安装清单分开存储，确保原生技能不会被错误卸载。

### 4.2 平台适配器

数据库中的平台定义是唯一事实来源。每个平台声明项目技能目录、用户技能目录、是否原生读取 `.agents/skills`、检测规则、最低版本、链接能力、原生安装能力和验证规则。

Codex、GitHub Copilot、Gemini CLI 和 OpenCode 可直接读取 `.agents/skills`。Claude Code 通过 `.claude/skills` 下的受管理链接适配。其他平台只有在适配规则经过验证后才显示安装成功。

### 4.3 技能包

技能包保存完整来源快照、来源 URL、Git 引用和提交、内容哈希、许可证、版本及更新状态。子技能保存相对路径、默认启用状态、是否必选和顺序。

技能包是版本、更新和卸载边界；子技能是搜索、分类、筛选和项目启用边界。相同内容可以复用底层数据，但不能丢失包归属和来源。

### 4.4 市场趋势

市场快照以来源、候选对象和采集日期唯一。GitHub 的真实增量必须由两个本地快照相减得到；历史不足时仅能提供明确标记的估算值。不同市场来源使用独立状态和错误信息。

## 5. 安装事务

通用安装流程：

1. 解析并校验来源。
2. 生成规范化来源身份和内容哈希。
3. 去重导入中央技能库或技能包存储。
4. 预览目标项目、冲突、平台适配和文件变更。
5. 创建软链接；失败时返回可识别的“需要复制确认”状态。
6. 用户确认后才执行复制。
7. 写入安装所有权清单并扫描验证。

平台原生安装必须额外展示 Hooks、插件和配置变更，且不得在导入阶段执行外部脚本。

## 6. 安全约束

- 所有写入路径必须经过规范化和包含关系检查。
- 拒绝路径穿越、中央库外覆盖和嵌套符号链接逃逸。
- 外部仓库导入期间不得执行脚本。
- 卸载仅删除安装清单中由应用拥有的路径。
- 包更新使用暂存目录和原子替换，失败时恢复旧版本。
- 本地修改与远端更新冲突时不得自动覆盖。

## 7. 迁移

- 扫描目录不会自动转换为项目。
- 现有项目、安装和技能记录原样保留。
- 来源明确且同属一个仓库根的技能可聚合为技能包；无法确认来源时继续作为独立技能。
- 新表和新列通过幂等迁移创建，重复启动不会重复数据。
- 迁移不得删除中央技能文件。

## 8. 验证

必须覆盖任意空目录添加、重复路径、失效项目、中央库单个和批量安装、无项目时即时添加、Windows 链接失败确认复制、平台适配、技能包完整导入和回滚、趋势快照、来源降级、平台排序、迁移重复执行和旧功能回归。

发布前运行前端类型检查、Lint、单元和交互测试，Rust 格式化、Clippy 和测试，随后生成 MSI 与 NSIS 包并完成启动冒烟验证。

## 9. 实现状态

0.11.0 已完成本文档中的核心领域模型和用户流程，包括独立项目页、中央库与技能集合优先的项目安装、外部技能先入中央库、技能包完整快照、子技能选择、平台适配记录、趋势快照、分类标签、更新筛选和本地项目使用次数排序。

平台原生包安装采用安全门禁：未验证清单或包含 Hooks 的包只允许通用技能安装，不会执行外部脚本。后续平台适配器通过验证后，可在不改变包模型的前提下开放原生变更。

验证结果和构建产物见[0.11.0 测试验证记录](../testing/0.11.0-测试验证记录.md)。
