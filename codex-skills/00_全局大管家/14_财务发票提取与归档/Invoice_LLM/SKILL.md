# 💼 Invoice_LLM 发票识别与报销录入技能

## 1. 核心法则 (Golden Rules)
- **了解指令**：执行发票大模型提取任务前，务必先使用 `view_file` 工具阅读本目录下的 `README.md`，了解环境依赖（如 PyQt6）和 API Key 配置方法（如 DashScope）。
- **人机协同**：该系统设计理念为“机器识别 -> 人工核对 -> 确认写入”，在执行相关报销台账生成时，建议保留人工复核环节。
- **保护隐私**：处理涉及财务隐私的发票文件时，确保在安全可信的环境下调用大模型 API。

## 2. 轨迹驱动执行引擎 (Execution Trajectory)
1. **输入阶段 (Initialization)**
   - 确定用户提供的发票图片或 PDF 文件目录。
   - 检查是否配置了相应的通义千问（Qwen-VL） API Key。
2. **提取阶段 (Extraction)**
   - 调用工具脚本，利用多模态大模型对发票/收据图像进行高精度识别。
   - 重点提取：发票号码、开票日期、校验码、税前金额、税额、价税合计金额等核心要素。
3. **输出与归档阶段 (Export)**
   - 将识别结果按特定报销格式导出为结构化台账（如 Excel 表格）。
   - 可选：根据配置，将原件重命名归档。
4. **输出验证 (Verification)**
   - 验证导出的台账数据字段是否完整，金额计算（税前+税额=合计）是否逻辑闭环。

## 3. 异常处理模式
- **依赖缺失**：如因环境未安装 PyQt6, pandas, PyMuPDF 等库报错，应提示用户按照 `requirements.txt` 进行安装配置。
- **大模型调用失败**：若因 API Key 无效或网络原因导致提取失败，应向用户报告错误，并提示检查大模型服务状态，或退回使用传统 OCR 方法。
