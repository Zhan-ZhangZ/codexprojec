# oh-story-claudecode 网文写作技能套件指南

## 1. 核心法则 (Golden Rules)
* **强制前置阅读**：由于该项目是一个庞大的多节点网文写作套件（内置多个子 skill），执行任何小说创作或逆向任务前，**必须**使用 `view_file` 查阅根目录下的 `README.md`，理解当前的创作阶段（如扫榜、拆文、写作、去AI味）及调用方式。
* **分阶段执行机制**：网络小说创作绝不能“一步到位”。必须严格按照环境部署 -> 扫榜选材 -> 拆文学习 -> 落笔创作 -> 精修定稿（去AI味）的生命周期推进。
* **套路与边界准则**：在重组大纲与写作时，必须严格遵守 `题材正文提示卡` 与 `大纲边界限制`，绝不可越界注水或脱离既定的情绪钩子。

## 2. 轨迹驱动执行引擎 (Execution Trajectory)
当你接收到撰写小说、分析网文榜单或润色章节的任务时，请依循以下状态机推进：

* **[State: 意图定位与环境探针]**
  * 使用 `view_file` 查阅 `README.md`，确定当前用户诉求属于哪个阶段（扫榜/拆文/大纲/正文写作）。
  * 识别是长篇（Long）还是短篇（Short）工作流。
  * 若为初次启动或需要初始化，引导执行 `setup` 环境部署流程。
* **[State: 子技能分发与执行]**
  * 依据当前状态，分别调用项目内的专项子能力（如 `story-long-scan` 扫榜、`story-short-analyze` 拆文、`story-long-write` 长篇落笔等）。
  * 在拆文与大纲构建阶段，需提取小说的节奏点、题材人设、矛盾冲突，建立个人的模块库。
* **[State: 对话与确认反馈]**
  * 大纲生成后，必须将核心钩子、章节定位（高压/推进/关系/低压）展示给用户确认，确认无误后方可进入正文渲染。
  * 短篇需特别关注付费点断点设计与知乎/番茄基调打磨。
* **[State: 去AI味精修 (Deslop)]**
  * 终稿生成后，必须经过自带的精修管道，剔除空泛词汇与说明文语态，确保提供具有“网文味”的强情绪价值文本。

## 3. 异常处理模式 (Exception Handling)
* **缺少大纲脉络**：若用户要求直接生成数万字长文，必须强硬中断，退回大纲设计与题材召回流程，强制建立章节结构。
* **定位文件缺失**：若未能在项目中找到指定的配置文件，必须提示用户运行 `/story-setup` 重新进行环境部署，并获取新版写入例外。
* **情绪母题冲突**：若在低压或过场章节中发现过多强行塞入的爽点与钩子，系统会触发警告（禁情绪母题扎堆），必须重写以保障叙事张弛有度。
