# 一份产品更新，改写成不同平台内容

先把事实固定下来，再改变表达。这个示例采用本项目一次真实配图修正，展示输入、提示词、成稿和编辑核对，不需要先调用图片服务或登录内容平台。

## 直接使用

1. 阅读 [facts.json](facts.json)，替换为自己已经核实的产品事实。保留已知、未知与禁止宣称的区分。
2. 将事实清单与 [prompt.md](prompt.md) 一起交给你已有的写作助手，补上目标平台、读者、内容形态和长度。
3. 对照 [outputs.md](outputs.md) 理解：短帖讲变化与边界，设计场景讲交付检查，问答解释如何判断。
4. 逐句审核事实映射。确认正文中的限制没有被标题或结尾推翻，再准备平台所需素材、AI标识和预览。

这是一份可复用的编辑工作样例，不是自动多平台发布功能，也不保证改写正确率。引用F编号只是让核对更容易，不能代替人工判断。

## 用一个错误反例测试

> “新模型自动修好错字，一键适配全部平台，免费生图。”

这段话应被退回：它把脚本更新说成新模型，与F5冲突；“修好错字”与F4冲突；“全部平台”超出F3；“免费”没有费用证据。即使字数很短、语气顺畅，也不能发表。

更准确的修改是：“配图脚本默认保留完整返回图；原图错字与最终发布尺寸仍需分别检查。”
