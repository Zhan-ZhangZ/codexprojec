# Ozon University：时效、来源冲突与回答核验门

> 审计日期：2026-07-22（Asia/Shanghai）  
> 审计范围：`01-official-rules.md`、`02-official-education.md`、`03-china-kol.md`；本次目录中尚无 `04`、`05`。  
> 用途：这是知识库的发布治理规则，不是 Ozon 平台规则。目标是阻止旧页面、其他市场规则、KOL 经验和易变数字被拼成一个看似确定的答案。

## 一、先执行的版本策略

### 1. 不设置一个全库“最新版本”，而给每条规则单独定版

每条可用于回答的事实至少登记：

`fact_id / 结论 / 来源 URL / 来源类型 / 适用卖家国家 / 履约方案 / 类目或工具 / 发布或生效日 / 最后核验日 / 易变等级 / 是否需后台确认`

当前研究文件统一视为 **2026-07-22 的研究快照**，不是“2026 年永久规则”。页面底部的 `©2024` 只是版权页脚，不得当成发布日期或生效日期。

### 2. 来源优先级先看“适用范围”，再看“新旧”

发生冲突时按以下顺序裁决：

1. **卖家当前账号中该功能的实际页面/提示**：用于确认功能是否可见、当前输入项和账号级费率；截图需带日期并隐藏敏感信息。
2. **适用于该主体的 Offer、合同及附件**：用于确认收费、责任、赔付、退货或处罚等有约束力事项。
3. **同一卖家国家、同一履约方案、同一工具的有日期官方公告或帮助页**。
4. **当前 Ozon Global 帮助中心中已选择正确国家和语言的页面**。
5. **无发布日期的官方帮助页、官方教育/类目研究**：只可说明页面当前展示或方法，不可凭页脚判断新旧。
6. **KOL、服务商和工具机构内容**：仅作实践假设与排查启发，不裁决平台规则。

“发布日期更晚”不能跨市场强行覆盖。例如，面向俄罗斯本土 Marketplace 账号的 2026 公告，不自动覆盖中国跨境卖家的 Global 帮助页；应先确认公告受众和卖家后台实际公式。

### 3. 易变等级与复核频率

| 等级 | 内容 | 知识库维护 | 回答用户时 |
|---|---|---|---|
| P0 即时核验 | 费率、物流价格/时效/路线、广告计费与最低门槛、退货期限/费用/责任、活动条件、处罚阈值 | 不把数字写成常量；只保留官方入口和核验字段 | 每次回答具体数字前查当日后台或适用官方页 |
| P1 高频变化 | 搜索权重、价格指数阈值/加成、内容评级公式、广告产品名与资格、仓库/承运商、后台路径 | 至少每月巡检；官方公告触发立即更新 | 数字和界面操作需当场复核；未核验只给排查路径 |
| P2 中频变化 | 上传方法、订单状态流、分析报表口径、履约流程 | 至少每季度巡检 | 涉及账号差异时核验；回答注明检索日期 |
| P3 稳定方法 | 漏斗诊断、全成本核算维度、先区分履约方案、事实与建议分层 | 半年复查 | 可直接作为方法，但不能派生平台未公布阈值 |

更新时保留旧结论为带日期的历史记录，不静默覆盖；需要写明 `supersedes` 或“适用范围不同”。

## 三、回答前的核验门

### Gate 0：先判定问题属于哪一层

- `平台事实`：资格、收费、期限、处罚、功能、状态、当前公式；进入 Gate 1—4。
- `运营诊断`：可以使用官方漏斗与全成本框架，但每项平台参数仍过 Gate 1—4。
- `实践观点`：可引用 KOL，但必须带作者、日期、来源性质和适用条件，并明确不是官方规则。

### Gate 1：收齐适用范围

至少确认：卖家注册国家、销售市场、商品类目、履约方案（FBP/realFBS）、当前账号语言/地区。订单问题再确认承运商、订单状态、发起方和时间；物流问题再确认始发地/目的地、重量体积和品类属性；广告问题再确认后台工具名与统计周期。

缺少会改变答案的字段时，不给具体数字，只列需要补充的字段和官方核验入口。

### Gate 2：判断是否命中 P0/P1

命中以下任一内容即触发当场核验：费率、金额、百分比、天数、重量、时效、路线、仓库/承运商、广告资格/计费/门槛、活动规则、退货/取消责任、处罚阈值、搜索权重、评级公式、后台按钮路径。

核验结果必须记录：`页面/后台名称 + 适用范围 + 核验日期 + 生效日期（若有）`。只有旧视频或无日期摘要时，视为“未通过”。

### Gate 3：处理来源冲突

1. 先比较国家、主体、履约方案、类目、账号资格是否相同。
2. 范围相同才比较发布时间/生效日；有生效日时优先于单纯发布日期。
3. 法律责任与费用以适用 Offer/合同/附件为准；功能可见性以当前账号为准。
4. 仍无法裁决时，同时披露两种口径及其范围，不替用户猜；建议把当前后台提示发给负责人或 Ozon 支持确认。

### Gate 4：限制答案强度

- 已核验：`截至 YYYY-MM-DD，在[国家/方案/工具]页面显示……；仍以订单/后台结算为准。`
- 仅有公开活文档：`官方帮助页当前展示……，页面无发布日期；请在你的账号中确认。`
- 仅有 KOL：`这是[作者]于[日期]的实践观点，可作为测试假设，不是 Ozon 规则。`
- 无法核验：只给排查步骤、所需数据和升级路径，不给伪精确答案。

## 四、四类高风险问题的最小检查单

### 费率与利润

卖家国家、类目、售价/币种、履约方案、重量体积、配送路线、退货成本、广告/活动、税费与汇率齐全后，才可做测算。把“官方当前费率”和“经营假设”分列，禁止用 KOL 旧视频中的百分比。

### 物流

确认 FBP/realFBS、始发地、目的地、承运商、交货点、商品属性、重量体积和订单状态。价格与时效只引用该路线当日页面或后台，不能用 `country=TR` 页面回答中国参数。

### 广告

确认当前工具名、账号是否可见、计费/归因口径、日期范围、曝光、点击、加购、订单、销售额和花费。没有这些数据只给漏斗排查，不给统一 CTR、预算或 ROAS 合格线。

### 取消与退货

确认履约方案、发起方、订单状态、是否已交运/签收、承运商、商品类目、销售国家和争议原因。期限、费用、责任、赔付与处罚每次查当期规则；涉及争议时升级 Ozon 支持/负责人，不作法律结论。

## 五、KOL 与官方规则的边界

KOL 可用于：提出检查顺序、对比运营流派、形成小规模实验、解释为什么要观察某些指标。

KOL 不可用于：证明注册/类目资格、当前佣金或物流费、退货期限、广告计费、处罚规则、搜索算法权重、工具数据准确率或收益承诺。

当 KOL 与官方冲突时，不写“KOL 错了”就结束，而应拆成两句：

> 平台事实：截至核验日，适用于该账号的官方页面/后台显示……  
> 实践参考：某作者在某日期建议……；可能基于旧版本、其他市场或特定样本，仅可作为测试假设。

这套分层同时保留实践价值，也防止实习生把经验意见执行成平台硬规则。

## 六、发布前阻断条件

出现下列任一情况，不允许生成确定数字或“必须/一定/保证”式答案：

- 未确认卖家国家或履约方案；
- 只有无日期帮助页与更新公告发生冲突，且未看到当前账号；
- 来源链接参数属于其他国家；
- 只有 KOL、机构营销页、视频标题或研究者推断；
- 官方正文读取失败，只拿到搜索摘要；
- 问题涉及费率、物流、广告、退货、处罚或合同责任，但未核验当期页面；
- 把相关性、实验结果或平台建议误写成因果保证。

通过这些阻断条件后，答案仍应附核验日期和适用范围；公开 Skill 不保存用户后台截图、订单号、合同或其他敏感信息。
