# 问题路由

先识别用户真正要解决的状态，不要只按关键词匹配。

| 问题状态 | 优先读取 | 首要目标 |
| --- | --- | --- |
| 无法发布、审核失败、搜索不到 | `listing-and-content.md` | 区分发布、审核、索引和内容质量问题 |
| 无曝光或曝光突然下降 | `traffic-and-funnel.md` | 检查可售状态、索引、需求、价格与流量来源 |
| 有曝光无点击 | `traffic-and-funnel.md` | 检查搜索意图、主图、标题、价格和竞争位置 |
| 有点击无下单 | `traffic-and-funnel.md`、`pricing-and-profit.md` | 检查商品页说服力、总到手价、评价、配送和库存 |
| 是否开广告、广告异常 | `ads.md` | 先确认商品页和经济模型，再讨论投放 |
| 定价、佣金、利润 | `pricing-and-profit.md` | 补齐成本字段，区分事实数字和敏感假设 |
| 物流、库存、配送、超时 | `fulfillment-and-after-sales.md` | 确认履约模式、责任边界和不可逆动作 |
| 取消、退货、争议 | `fulfillment-and-after-sales.md` | 先止损和保留证据，再查责任与规则 |
| 选品、铺货、精品、KOL 观点 | `practitioner-frameworks.md` | 呈现策略适用条件和分歧 |
| “最新规则”“准确费率” | `source-policy.md` | 先核验官方最新来源 |

## 模糊问题的最少追问

只追问会改变判断的问题，通常不超过三项：

- 站点、类目和履约模式是什么？
- 当前处于曝光、点击、加购、下单还是履约哪个阶段？
- 有哪些可用数据，观察窗口多长？

用户没有数据时，先给最小采集清单，不假装已经完成诊断。
