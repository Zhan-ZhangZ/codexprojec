# 歸藏材质插画 Skill 指南

## 1. 核心法则 (Golden Rules)
* **强制前置阅读**：在调用该技能或处理复杂图表、冷门概念前，**必须**使用 `view_file` 查阅 `README.md` 及 `references/` 目录下的相关规范（如 `visual-style.md`、`prompt-patterns.md`），以确保生成的提示词完全符合歸藏视觉系统。
* **数据严谨原则**：处理图表重绘时，绝对不能篡改数值、坐标和单位；仅抽取核心语义并进行视觉优化。
* **中文标签优位**：除非用户特别指定外语，图内解释性文字、箭头标签等必须使用简短、具体的中文，避免抽象名词堆砌。

## 2. 轨迹驱动执行引擎 (Execution Trajectory)
严格按照以下状态机轨迹执行插画生成任务：

* **[State: 意图剖析与寻址]**
  * 使用 `view_file` 查阅 `README.md` 与参考文档。
  * 判断用户需求的插画类型（如流程图、机制图、图表美化、人文场景等）。
  * 若涉及冷门概念、特定品牌或科学装置，必须先行查阅相关信息，提取稳定的视觉线索。
* **[State: 结构降维与标签提取]**
  * 将复杂的原文或图表解构。对于非图表概念，压缩为一句话说明及 3-5 个可见的简短中文标签（2-6 个汉字）。
  * 选择匹配的视觉结构（如循环、管道、中心辐射、分层叠加等）。
* **[State: 提示词工程构建]**
  * 基于 `assets/prompt-template.md`，撰写严格符合比例、安全区和材质风格的生图提示词。
* **[State: 图像生成与 QA 校验]**
  * 调用生图能力（如 GPT-Image）。
  * 遵循 `qa-checklist.md` 对生成的图像进行检查。若中文标签错乱、图表数据失真或主体被裁切，必须带约束条件重新生成。
  * 将最终提示词与图片路径交付给用户，或传递给后续的 `guizang-social-card-skill` 进行排版。

## 3. 异常处理模式 (Exception Handling)
* **生图能力受限**：如果当前环境无法直接生成图片，必须向用户完整输出最终优化的 Prompt 方案和本地工作流建议。
* **概念极度模糊**：若用户提供的原始材料过于抽象且无从查证，必须退回 [State: 意图剖析]，向用户追问具体的实体隐喻或视觉倾向。
* **外部组件缺失**：该技能专注中心配图。如果用户需要完整的版式排版（如小红书卡片），请主动提示并推荐唤醒配套的 `guizang-social-card-skill`。
