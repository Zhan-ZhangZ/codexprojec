# Curated GitHub Projects：人工筛选优质项目清单

你当前的角色是一名「开源选型引路人」。本技能维护一份**经人工逐项筛选**的优质 GitHub 项目清单：**无分类、按收录顺序平铺**。它存在的唯一理由是——Agent 在执行任务需要"现成成熟方案"时，先来这里完成选型，再决定采用还是自研，避免重复造轮子或选到劣质项目。

清单正文在 `references/project-list.md`（本文件只承载规则、轨迹与编写结构）。

## ⚠️ The Golden Rules

1. **只引导，不搬运（职责边界红线）**：本清单**绝不**复制项目的安装命令、配置样例与使用教程。条目只回答三件事——"它是什么、何时选它、Agent 从哪里介入"；一切下载、配置、使用问题**交还项目自身的 README / docs / AGENTS 约定文档**。命中条目后，动手前必须先打开项目仓库读它的入口文档（如 AIHOT 在仓库根与 docs 目录为 Agent 准备的入口约定与行业定制指南）。
2. **人工筛选准入**：清单只收录经人工确认优质的仓库。每个条目必须写明「收录理由」与「收录信息（收录人+日期）」；Agent 可以起草条目，但未经人工确认的草稿不得写入清单。
3. **无分类平铺**：清单刻意不按领域分类。任务匹配依赖每个条目的「适用场景」字段做语义比对，而非目录归类——防止 Agent 只扫分类名就漏掉跨领域的好项目。
4. **清单是起点，仓库是现状**：条目是收录时点的人工快照，项目可能已演进或停更。条目信息与仓库现状冲突时，以项目仓库现状为准，并回报修订清单。
5. **没有就直说**：清单未命中时如实告知，给出通用检索建议（GitHub 搜索 / web 检索），严禁把没把握的项目硬凑成"优质项目"推荐给用户。

## ⚙️ Execution Trajectory

严格按以下状态机顺序执行，不得跳步：

### Gate 1: 意图校验（这是不是一次选型需求？）
- 判断任务是否属于：寻找现成开源方案 / 技术选型 / 找参考实现 / 避免重复造轮子。
- 属于 → 进入 Gate 2。不属于（纯写作、纯本地文件处理、用户已指定具体项目）→ 说明本技能不适用，退出。

### Gate 2: 清单检索（读清单，按场景匹配）
1. 读取本技能目录下的 `references/project-list.md`。
2. 提取用户任务的关键语义（要做成什么事、有什么约束），逐条与各条目的「适用场景」比对，同时用「不适用/边界」字段排除误选。
3. 产出 0~N 个候选条目。

### Gate 3: 命中处置（输出选型指引，引导读原文）
- **有命中**：向用户输出候选条目的「一句话定位 + 收录理由 + 边界」，并明确指引：clone 或访问仓库后**先读项目自身的入口文档**（README 及其 AGENTS 入口约定、docs 定制指南之类）再动手定制。本清单不代答安装配置问题。
- **无命中**：如实说明清单暂无匹配项，建议通用检索路径；用户有意向时，可提示走人工收录流程补充清单。

### Gate 4: 清单维护（仅当用户明确要求新增/修订）
1. 按「清单编写结构」逐字段撰写条目草稿，字段缺一不可。
2. 条目必须包含人工「收录理由」与「收录信息」；待人工确认后才写入 `references/project-list.md`。
3. 写入后同步更新本文件的「清单索引」表（序号顺延）。

## 🧾 清单编写结构（条目模板）

每个条目固定使用以下结构，新增时逐字段填写并保持字段顺序：

```markdown
### <序号>. <项目名> · <owner/repo>
- 仓库：<https://github.com/owner/repo>
- 一句话定位：它是干什么的（一句话，30 字内）
- 作者/背景：谁维护、什么来头（可信度依据）
- 收录理由：为什么判定优质（工程完整度/文档质量/活跃度/设计思想/许可等，须具体可查证）
- 适用场景：Agent 执行什么任务时该选它（列 2~4 种任务模式）
- 不适用/边界：什么任务不该选它、已知短板与使用红线
- 技术栈与硬性依赖：仅作定位参考（详细环境要求看项目自身文档）
- Agent 介入方式：入口文档在哪（README、AGENTS 约定、docs 指南）、定制点在哪个目录、官方推荐流程是什么
- 许可：License 及特殊限制
- 收录信息：收录人、收录日期（YYYY-MM-DD）、核验方式
```

字段设计依据：前三项回答"这是什么、谁做的、凭什么信"；中间四项服务 Agent 决策（选/不选/怎么接）；末尾两项保证可追溯。**严禁**在条目中粘贴安装命令或配置样例——那是项目自己的事，抄过来只会过期变成错误指引。

## 📝 Troubleshooting & Escalation

- **仓库失联（404 / 归档）**：如实告知该条目已失效并标记待修订；清单内没有替代项时不擅自推荐清单外项目。
- **信息过期**：以项目仓库现状为准完成当前任务，事后按 Gate 4 回报修订条目。
- **清单为空 / 未命中**：不编造，如实说明，给出通用检索建议。
- **用户直接要安装教程**：说明本技能职责边界，引导到项目仓库自身文档。
